## 一、它是什么

**一句话**：让 agent 能问一个**专门的判断模型**要一个**结构化的答案** ——
是/否、选哪个、给几分 —— 而**不要它写一句话**。

**链路：**

```
dsh agent  →  jev_ask / jev_check / jev_rank  →  dsh-wsl-jev  →  HTTPS_PROXY
                                                                      ↓
                                        OpenRouter 或 TypeSafe /v1/systemone
```

**四个工具：**

| 工具 | 做什么 | 返回 |
|---|---|---|
| `jev_status` | 诊断：provider / endpoint / 有没有 key / 代理 | 状态行 |
| `jev_ask` | 对一段 `state` 提 typed 问题（可多题） | `noul` / `choice` / `score` + confidence |
| `jev_check` | 单题：证据是否支持某个 claim | 一个 `noul` 值 |
| `jev_rank` | 从 2~32 个候选里选最贴合 query 的 | pick + 概率分布 + confidence |

**型号与端点：** 模型 `jev-latest`（实测解析为 `typesafe/jev-1.13-20260917`），
provider `auto` → 优先 `OPENROUTER_API_KEY`，否则 `TYPESAFE_API_KEY`。

## 二、实测数据（2026-09-29）

**这是本文最有价值的部分 —— 因为它可复现。**

### 2.1 `jev_check` 一次

```
claim       "这个插件返回 typed verdict 而不是 prose"
evidence    一段 200 字的说明
─────────────────────────────────────────────────
model       typesafe/jev-1.13-20260917
latency     2662 ms
answer      {"supported": {"type": "noul", "noul": 0.97}}
usage       输入 481 token · 输出 20 token
cost        $0.000020202
```

### 2.2 `jev_rank` 一次（四选一）

```
query       「一键安装入口该放哪」＋ 一段背景（约 60 词）
candidates  4 个方案
─────────────────────────────────────────────────
latency     1931 ms
pick        "放进现有 dsh-wsl-kit 元仓"      ← ★ 与我自己的判断一致
confidence  0.51
概率分布    c1 0.63 · c0 0.19 · c3 0.16 · c2 0.02
usage       输入 459 token · 输出 50 token
cost        $0.000019278
```

### 2.3 关键比率

```
★ 输出 20~50 token —— 而一次普通 LLM 对话动辄几千
★★ 成本 ≈ $0.00002/次（约 ¥0.00015）—— 十万分之二美元
★★★ 延迟 1.9 ~ 2.7 秒
```

**这意味着：可以问很多次。** 一次普通对话的钱能问几百次。

## 三、优点

### 3.1 ★ 一等的优点：**它给的是概率，不是断言**

```
{"c2":0.02, "c3":0.16, "c1":0.63, "c0":0.19}
```

**★★ 这是普通 LLM 给不了的东西。** 让 agent 自己说"我有多确定"，那是**自我报告**；
而这里是一个专门的模型在**打分**。

**★★★ 实用后果：**
```
· 0.63 → 有明显倾向，但不压倒
· 0.02 → 几乎可以排除
· confidence 0.51 → ★ 它自己承认"这个判断不牢" —— 那就别当定论用
```

### 3.2 输出极短，所以**便宜且快**

```
20~50 token 输出 / 2 秒 / $0.00002
★ 对比：一次普通对话 几千 token / 十几秒 / 高两个数量级
```

**★★ 这让"多问几次"变成可行策略** —— 换个问法、换个 state 描述，再看答案稳不稳。

### 3.3 只回答，不发挥

```
★ 它不会"顺便给你建议"，不会写铺垫，不会反问你
★★ 对【需要判定的地方】这正好 —— 你拿到一个数就能往下走
```

### 3.4 自包含

```
★ 不依赖第三方 Jev dsh/MCP 插件，直接打 HTTP
★★ 所以它不受别人的协议变更影响
```

### 3.5 与 agent 的接口是**类型化**的

```
jev_ask 的每题必须声明 type: noul | choice | score
★ 而每题可以带 criteria（true/false 各是什么意思）
★★ 所以问题被迫写清楚 —— 这本身就是收益
```

## 四、缺点与限制

### 4.1 ★ 它不是"第二个意见"，它只是一个模型

```
★ 实测 model = typesafe/jev-1.13-20260917，一个具体版本的判断模型
★★ 它会有系统性偏差 —— 而且比普通 LLM 更难察觉，
   因为输出只有几个数字，你看不到它的推理过程
★★★ 所以「0.97」不等于「97% 的概率这事为真」，那是模型的输出，不是校准过的概率
```

### 4.2 ★ 看不到推理，所以**无法反驳**

```
普通 LLM 说错了，你能从它的理由里看出破绽
jev 说 noul=0.97，你只能接受或拒绝 —— ★ 说不出"它哪里想错了"
```

**★★ 这是它最大的代价：可调试性差。**

### 4.3 问题是**封闭式**的

```
noul    是/否
choice  给定候选里选一个
score   打分
★ 你没法问"该怎么做" —— 只能问"这两个哪个更…"、"这有没有…"
★★ 所以用它之前，你得先把开放问题【压缩成选项】—— 而那一步是最难的，它帮不上
```

### 4.4 ★ 依赖外部 API（OpenRouter / TypeSafe）

```
· 要 key、要代理（WSL 里通常必须）
· 断网就用不了
· ★ 而且它把判断送去了第三方 —— 敏感内容别问
```

**★★ 本机实测的 provider 是 OpenRouter，也就是**国外服务** ——
与「国产化」的取向有张力。**（这一点值得你自己权衡。）

### 4.5 延迟 2 秒不算低

```
★ 如果在一个循环里问 20 次，那就是 40 秒
★★ 它适合"关键分叉处问一次"，不适合"每步都问"
```

### 4.6 ★ confidence 0.51 那次说明了它的边界

```
四选一的实测: confidence 0.51，最高概率 0.63
★ 也就是说【它自己认为这个判断不牢】
★★ 而我（一个 LLM）对同一问题有更明确的判断 —— 因为它看得到我们的全部上下文
★★★ 所以: jev 不知道你的项目历史。它的判断只基于你给的那段 state
```

**★★★★ 这是最实用的一条限制：`state` 里没写的，它不知道。**

### 4.7 文档滞后

```
README 写「插件 0.1.0 / 最新验证 0.1.7-alpha.2」
★ 而本机装的是 0.2.0、dsh 已到 0.2.0-rc.2
★★ 小问题，但说明兼容性表没跟上
```

## 五、实际用途

### 5.1 它**擅长**什么

| 场景 | 为什么合适 |
|---|---|
| **关键分叉处要一个第二意见** | 拿到一个带概率的判定，而不是一段话 |
| **在多个方案里排序** | `jev_rank` 直接给概率分布，`c2:0.02` 这种信息很有用 |
| **验证一个 claim 有没有证据支撑** | `jev_check` 就是为这个设计的 |
| **要给一批东西打分** | `score` 类型批量问，便宜 |
| **筛选：先粗筛再细看** | 便宜快速 → 用它砍掉明显不行的，再让人/LLM 细看 |

### 5.2 它**不擅长**什么

| 场景 | 为什么不行 |
|---|---|
| **需要理由的决策** | 它不给理由，你无法从它那里学到什么 |
| **依赖项目上下文的判断** | ★ 它只看 `state`；项目历史它不知道 |
| **开放式问题** | 只能 noul/choice/score，得你先压缩成选项 |
| **敏感内容** | 走第三方 API |
| **每步都调用** | 2 秒延迟累积起来很可观 |
| **替代 LLM 判断** | ★ 它是补充，不是替代 |

### 5.3 ★ 我认为最合适的用法

```
① 只在【关键分叉】用，不在每步用
② state 写得尽量自包含 —— 因为它不知道你的历史
③ ★ 看 confidence，不看单个数字:
     confidence 高 + 某个概率压倒  → 当参考
     confidence 低（如 0.51）      → ★ 当"没有信息"，别当结论
④ 与我自己的判断【对比】，不一致的地方才是值得看的地方
```

**★★ 第 ④ 条是它的真正价值：不是替我做决定，而是**指出我们哪里不一致**。**

## 六、本机配置

```
状态      provider=openrouter  model=jev-latest  hasKey=true
          proxy=true  proxyMode=via-proxy  egress=ON when tools called
env       ~/.dsh/dsh-wsl-jev.env（4 行，0600）
安装      dsh plugin --profile web add github:173787247/dsh-wsl-jev
          ★ 可选插件，不在 KIT_SET=daily / install.sh
冒烟      bash scripts/probe-jev.sh
```

**配置项：**

```yaml
- id: dsh-wsl-jev
  config:
    enabled: true
    provider: auto          # auto | openrouter | typesafe
    model: jev-latest
    timeoutMs: 15000
```

## 七、一句话结论

```
★ 它是一个【便宜的、快速的、只说数字的判断器】。
★★ 优点: 概率分布 + 极低成本 + 类型化接口
★★★ 缺点: 看不到推理、不知道上下文、只能回答封闭问题
★★★★ 所以: 在关键分叉处问它一次，然后拿它的答案【与自己的判断对照】——
         不一致的地方，就是值得再看一眼的地方。
```
